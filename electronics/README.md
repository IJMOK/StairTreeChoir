# Tree controller and site wiring (M4)

One controller per tree: an ESP32 dev board running WLED, a 74AHCT125 level shifter and a Mini560 5V buck on a 5×7cm prototype board, in a printed box (`enclosure/tree-box.scad`) on the tower of the tree's left boot (`feet/`), behind the tree. The board takes 12V and gives out one 5V data line. The pixels' own 12V never runs through the board.

- [tree-controller-board.svg](tree-controller-board.svg): where every part goes, plus the joins on the underside (mirrored, as you see it when soldering).
- [connections.md](connections.md): the same as a list: every part's holes, and every join with its hole names.

Both are generated by `tools/gen_controller.py` (`make all`). Change the generator, not the files.

## Schematic

```
   (fused 5A at the site box)
12V flex + ───────────────┬──────────────────────────────► pixel string +12V (xConnect)
(PG9)                     │                    Wago 221
                          │
                          └── JP 12V ── Mini560 IN+          Mini560 OUT+ ── 5V rail
12V flex − ───────────────┬──────────────────────────────► pixel string GND
                          └── JP GND ── Mini560 IN− ── OUT− ── GND rail

5V rail ── ESP32 5V (J2.19) ── U1.14 VCC ── C1 100µF ── C2 0.1µF (at U1) ── GND rail

ESP32 IO16 (J3.12) ──┬── U1.2 (1A)      U1.3 (1Y) ── R1 33Ω ── JD DATA ──► pixel string DATA
                     └── R2 10k ── GND
U1.1 (1/OE) ── GND                       (channel 1 always enabled)
U1.4, 5, 9, 10, 12, 13 ── GND            (spare channels tied off)
U1.6, 8, 11 ── open                      (spare outputs)
ESP32 GND (J3.1) ── GND rail
```

Why each part is there:
- **74AHCT125**: the ESP32 gives 3.3V logic; WS2811 pixels on 12V want close to 5V. An AHCT part powered at 5V reads 3.3V as a clean high. In a socket, so a dead one is a 10-second swap.
- **R1 33Ω**: damps ringing on the data lead.
- **R2 10k pull-down**: holds the data line low while the ESP32 boots, so the tree doesn't flash random colours at power-on.
- **C1 100µF, C2 0.1µF**: bulk and local decoupling for the 5V rail.
- **GPIO16**: not a boot strapping pin, works with WLED's LED output, and is what the M0 prototype ran on.
- **GPIO 5, 18, 19, 23 stay free.** They are the ESP32's usual SPI pins for a micro-SD card. If Wi-Fi streaming proves too jittery, a £1 SD breakout wired there keeps the ESPixelStick FPP Remote option open (M0 decision) without new boards.

## Inside the box

- 12V comes in on 3-core flex through the PG9 gland in the box floor. It is already fused (5A) at the site box, where the run starts, so the fuse protects the flex as well as the tree. There is no fuse in the tree box.
- Two Wago 221-413 lever connectors split the supply: one joins +12V to the pixel string and to JP 12V, the other joins GND the same way. The pixel current (about 2.3A at full white) stays on 18AWG wire and the Wagos, never on the prototype board.
- The pixel lead leaves through the PG7 gland in the box floor, as a short round tail ending in an xConnect plug down in the boot tower, where the tree's own pigtail comes up from the shelf hole. Its data wire goes to JD DATA. JD GND is spare: fit the optional TVS diode across JD (DATA to GND) if you use one.
- The Mini560 sits off the board on short leads (double-sided foam tape to the box floor), wired to the four pads in column A.
- The ESP32 and U1 plug into sockets, so a controller can be swapped without a soldering iron.
- **Antenna**: the WROOM-32U has a U.FL socket on the module. Use a U.FL to RP-SMA bulkhead pigtail and a small dipole on the outside of the box, pointing up beside the tree. 30mm of wet oak between the antenna and the router costs signal, so put the box on the side of the tree that faces the router where you can.

**Unverified until the parts arrive:**
- xConnect wire colours (which is data). Check against the arrows on the string and with a meter before connecting anything.
- The ESP32 board's header row spacing. The layout assumes 25.4mm (10 holes). Measure it and set `ESP_ROW_GAP` in the generator if it differs.
- The Mini560's size and pad positions.
- That a 5×7cm board here is 24×18 holes.

## Power and USB: never both

Espressif's DevKitC guide says to power the board from exactly one source: USB, *or* the 5V pin, *or* the 3V3 pin. On this board the 5V pin is always fed by the Mini560, so:
- update WLED over Wi-Fi (Config → Security & Updates → Manual OTA), which needs no cable;
- if you must use USB, unplug the 12V first, or pull the ESP32 out of its headers and flash it on the bench.

## Building and testing one board

1. Solder the headers, the DIP socket, the terminals and the passives. Don't fit the ESP32, U1 or the Mini560 yet.
2. Do the underside joins from connections.md, ticking them off. Bridges are a solder blob between neighbouring holes; everything else is insulated wire.
3. Continuity check: 12V, 5V and GND are not shorted to each other. 12V reaches only JP 12V and the Mini560 IN+ pad.
4. Wire the Mini560 in. Bench supply at 12V, current limit 200mA, into JP. Check 5.0V (±0.1V) at J2.19 and at U1.14 (socket pin 14). A Mini560 of the wrong voltage version shows here, before it can kill an ESP32.
5. Power off. Fit U1 (notch to the right, towards R1) and the ESP32 (antenna end left). Power on: the ESP32's LED lights and WLED joins Wi-Fi; current should sit under 150mA at 12V.
6. Connect the pixel string through the Wagos and JD. First-light test in WLED (solid red, then green, then blue) to confirm the colour order; then the xLights test chase to confirm node 1 and the wiring order match the model.

Full-white current per tree and the soak test belong in docs/test-checklist.md (M6).

## Site wiring

Decided 23 Oct 2026: one PSU per site, star-wired from an outdoor site box.

```
Mains (RCD socket) ── Mean Well LPV-xxx-12 (IP67, outside any box, beside the site box)
                         │ 12V
                    Site box ─┬─ 5A fuse ── 3-core flex ──► Tree 1 boot/box ── pixels
                              ├─ 5A fuse ── 3-core flex ──► Tree 2 boot/box ── pixels
                              ├─ ...  one fused run per tree
                              ├─ PAM8610 (12V) ── speaker
                              └─ 12V→5V buck ── Pi (FPP) ── USB sound card ── PAM8610
                                                  │ Ethernet
                                             Site router ·····Wi-Fi·····► every tree's ESP32 (DDP)
```

| Site | Load at full white (2.3A per tree + ~1.5A amp/Pi) | PSU |
|---|---|---|
| 6 trees | ~15.5A | LPV-200-12 (16.7A) |
| 4 trees | ~11A | LPV-150-12 (12.5A) |
| 2 trees | ~6A | LPV-100-12 (8.5A) |

- Voltage drop: 2.3A over 5m of 0.75mm² flex (10m of conductor, ~0.26Ω) is about 0.6V, so a tree sees ~11.4V; fine for 12V pixels. Past about 8m use 1.5mm² flex.
- The fuse sits where each run starts, so it protects the flex (a fuse at the tree end would not). 0.75mm² flex is good for ~6A; 5A fuses suit it.
- Mains never enters a printed box. A Pi 5 in the site box needs a 5V 5A buck; a Pi 3 is happy with 2.5A.
