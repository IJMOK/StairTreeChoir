# xLights model

`StairTree.xmodel` is generated by `tools/gen_xmodel.py` from `data/tree-layout.json`. Don't edit it by hand; change the layout and run `python -m tools.build`.

## What's in it

- **Custom model**, 39 × 90 grid at 10mm per cell, so it has the tree's real proportions. Node numbers are in wiring order (1 = base-left, data in).
- **Face definition** "StairTree" (Node Ranges), so the Faces effect and lip-sync work straight away:

| Face key | Nodes | What lights |
|---|---|---|
| Mouth-rest, Mouth-MBP | 74-80 | lip line |
| Mouth-etc, -E, -FV, -L | 69-80 | lip + small arc |
| Mouth-AI | 60-68, 74-80 | lip + wide arc |
| Mouth-O, -U, -WQ | 60-73 | small + wide arcs |
| Eyes-Open | 81-92 | both hexagons |
| Eyes-Closed | 83-85, 89-91 | lower half of each eye (blink) |
| FaceOutline | 1-59 | tree outline |

  Custom colours are on: mouth red, eyes white, outline green. Turn "CustomColors" off in the face definition dialog to colour them from the effect palette instead.
- **Sub-models**: Outline, Mouth, Mouth Wide, Mouth Small, Lip, Eyes, Eye Right, Eye Left.

Format checked against the xLights source (commit 75c3e11, 20 Oct 2026). **Not yet tested in xLights itself**: the first import is the real check.

## Setting up the 6-tree layout

1. Use a show folder outside this repo (e.g. `Documents\xLights\StairTreeChoir`); xLights writes large render and backup files there.
2. On the Layout tab, import `StairTree.xmodel` with xLights' custom model import (Download/Import Models). Name it `Tree1`.
3. Check: 92 nodes; the face appears under the model's Faces; node 1 is bottom-left.
4. Copy and paste it to make `Tree2` … `Tree6` and space them out on the layout.
5. Channels (CLAUDE.md §2): slot s starts at channel (s-1) × 276 + 1, 276 channels each, so Tree1 = 1, Tree2 = 277, Tree3 = 553, Tree4 = 829, Tree5 = 1105, Tree6 = 1381.
6. For testing from the PC with the spare ESP32: add an Ethernet controller of protocol DDP at the ESP's IP, 276 channels, and assign `Tree1` to it. WLED on the ESP needs 92 LEDs and its realtime (DDP) receive enabled.
7. Make a group "All Trees" with Tree1–Tree6 for whole-show effects.

Later, the per-site FPP config (M5) sends each slot's channels to the right tree by IP.

## Rob's show folder as set up (21 Oct 2026)

Show folder `Documents\xLights`, models StairTree1–6 (not Tree1–6 as above).

- **Six controllers, one per sequence slot**: Slot1 … Slot6, Ethernet, DDP, 276 channels each, in that order, so their global ranges are 1, 277, 553, 829, 1105, 1381 whatever else is added. Slot1 points at the prototype ESP32 (192.168.0.72) and is Active; Slot2–6 have placeholder IPs (192.168.0.202–206) and are Inactive (they hold their channels but send nothing). Set a slot Active with a real IP when its tree controller exists.
- **Each tree is pinned to its slot**: StairTreeN has Controller `SlotN` and start channel `!SlotN:1` (channel 1 of controller SlotN; syntax from xLights `Model.cpp`). Plain DDP controllers without a vendor aren't auto-laid-out by xLights (`ModelManager::ReworkStartChannel`), so these stay put.
  Why: with one controller and the others "No Controller", xLights had moved the trees to absolute channels 277…1657, so sequence data for StairTree1 fell outside the ESP32's range.
- **Group** `Choir` = StairTree1–6, for whole-choir effects.
- **Automation**: Preferences → Output → API Port = Port A (49913). xLights then answers the REST/xlDo commands and MCP (`POST /mcp`) on 127.0.0.1:49913. It can't edit controllers, model channels or groups; those need the layout files edited with xLights closed. Only one xLights may run: a second copy can't take the port and the first may save over edited files.

Verified 21 Oct 2026: `getControllers` reports Slot1–6 at 1/277/553/829/1105/1381, and a sequence with an effect on StairTree1 played to the ESP32 (WLED live, DDP from the PC).

## Sequencing a song (first done 21 Oct 2026: Rockin' Around the Christmas Tree)

The file names in this section are as first done; since 24 Oct 2026 song files live in `Audio\Songs\` named after the sequence (see the per-song checklist below, [docs/folders.md](../docs/folders.md) and [docs/show-folder-moves.md](../docs/show-folder-moves.md)).

1. Put the MP3 in `Documents\xLights\Audio\`.
2. Lyric timing on the PC (no paid service): `.venv/Scripts/python -m tools.lyric_timing "<mp3>" --artist "..." --title "..." --model small.en`. It downloads the lyrics from LRCLIB into `<mp3>.lyrics.txt` (fix and rerun if needed), aligns every word with Whisper (about 1 min for a 2-minute song on the CPU), writes `Audio\Choir.json`, and lists words missing from xLights' dictionaries. Add those to `Documents\xLights\user_dictionary` (CMU phonemes; xLights reads the show folder's copy first).
   Sanity check: compare line starts with LRCLIB's synced timestamps. For the first song all lines agreed within 1.6s except one LRCLIB had put at the start of the sax break; a cold Whisper transcription of that window confirmed no singing there, so the alignment was right.
3. New sequence (automation `GET /newSequence?media=<url-encoded path>&frameMS=50&view=All%20Models`, or File → New): xLights then shows Sequence Settings, which needs a click. 50ms frames.
4. Import the timing: right-click the timing area → Import Timing Track(s) → type "Eleven Labs (*.json)" → `Choir.json`. Right-click the track → Breakdown Words. (It may be named `Choir_1` if a Choir track existed.)
5. Faces effect on every tree (automation `addEffect` on StairTree1, then `cloneModelEffects` to 2–6): `E_CHOICE_Faces_TimingTrack=<track>, E_CHOICE_Faces_FaceDefinition=StairTree, E_CHOICE_Faces_Eyes=Auto, E_CHOICE_Faces_EyeBlinkFrequency=Normal, E_CHECKBOX_Faces_Outline=1` (keys from xLights `FacesEffect.cpp`). Render, save.
6. Check the render from the `.fseq` (v2, zstd): every tree uses all four mouth shapes, rests on the lip during instrumentals, blinks.

Automation quirks seen: `POST /xlDoAutomation` returned "No command" for `newSequence` with a media path and for `exportModel`; the GET forms work. `newSequence` returns before the Sequence Settings dialog is closed, and nothing can be saved until it is.

### Arranging: parts and beat lighting

`data/songs/<song>.json` says which tree group sings each lyric line (by number, no lyrics in git) and how the outlines light per section; `python -m tools.arrange_song data/songs/<song>.json` (sequence open in xLights) replaces each tree's effects: Faces segments (lyric track while singing, "rest" otherwise; Faces outline off) and one On effect per beat on `StairTreeN/Outline` (sub-model effects render over the model's). `--dry-run` prints the plan. Re-run after any change; it takes ~20s.

Beats: `librosa.beat.beat_track` on the MP3 → `Audio/beats.json`, now `Audio/Songs/Rockin Around the Christmas Tree.beats.json` (Rockin': steady 72 BPM, 143 beats).

Rockin' arrangement (21 Oct 2026): verses call-and-response between StairTree1–3 and 4–6; bridges build from the outer pair (or inner pair the second time) to the full choir; refrain and finale all six. Outlines: green verses, gold bridges, red/green refrains, a one-tree-per-beat ripple through the intro and sax break, singers bright and resting trees dim. Verified from the render: on all 22 lines exactly the arranged trees' mouths move.

### Per-song checklist (as of the second song, Dominick the Donkey, 21 Oct 2026; file names as of 24 Oct 2026)

Naming rule: every file of a song shares its **sequence name** (what the `.xsq`/`.fseq` and the FPP playlists call it). The sequence sits in the show folder's top level; its audio, lyrics, beats and timing go in `Audio\Songs\`: `<Sequence name>.mp3`, `.lyrics.txt`, `.lrc`, `.beats.json`, `.timing.json`. Skits use their script name in `Audio\Skits\` (tools/skit.py does it).

0. Copy the MP3 to `Documents\xLights\Audio\Songs\<Sequence name>.mp3` (e.g. `Feliz Navidad.mp3`).
1. `python -m tools.lyric_timing "Audio/Songs/<Sequence name>.mp3" --artist ... --title ... --model small.en` → `Audio/Songs/<Sequence name>.timing.json` (+ `.lyrics.txt`, `.lrc`). It strips brackets from words (backing vocals stay bracketed in the line text), falls back to LRCLIB timing on lines Whisper loses (donkey brays), removes overlaps and gives every word ≥ 0.1s so xLights can break it down. Add any words it lists to `Documents\xLights\user_dictionary`, then **restart xLights** (it loads dictionaries once).
2. `python -m tools.beats "Audio/Songs/<Sequence name>.mp3"` → `Audio/Songs/<Sequence name>.beats.json`.
3. New sequence without the GUI (24 Oct 2026): `python -m tools.xsq "<Sequence name>" --clone "<an existing song>" --media "Audio/Songs/<Sequence name>.mp3" --track <Track>`, then `python -m tools.xl_timing add ... --name <Track> --replace` (skits: clone `Skit tuning-up`). Or by hand: New sequence (click through Sequence Settings), save as `<Sequence name>.xsq` in the show folder's top level. Open sequences by full path with forward slashes in the automation API: a bare name can open the wrong one (`Goodnight.xsq` opened `Skit goodnight.xsq`). Add the timing track under a short distinct name (e.g. `FelizNavidad`): with the sequence closed, `python -m tools.xl_timing add "<Sequence name>" "Audio/Songs/<Sequence name>.timing.json" --name <Track>`; or import the `.timing.json` (Eleven Labs type; xLights names the track after the file, so rename it), Breakdown Words, save.
4. Write `data/songs/<song>.json` (`audio`, `lyrics_timing`, `beats` relative to the show folder, `lyrics_track` = the track name) and `--dry-run` it to check the balance of who sings how much.
5. `python -m tools.arrange_song data/songs/<song>.json`, then `python -m tools.check_render data/songs/<song>.json`: every line's singers must match the arrangement.

Back-to-back lines (Dominick) taught two rules now in `arrange_song`: a singer's lead-in/tail stops halfway to the neighbouring line, and windows merge only across silence, never across someone else's line.

## Looks: the effects library (23 Oct 2026)

Each section in `data/songs/<song>.json` names a **look** (tools/fx.py) instead of just outline colours:

```json
{"name": "verses", "until": 33.0, "look": "chase", "palette": "rainbow",
 "accent": "colour_hit", "accent_every": 2, "eyes": "follow"}
```

- **Per-tree looks** on `StairTreeN/Outline`, bright on the singers and dimmed on the rest: `chase`, `marquee`, `candy`, `rainbow_wash`, `twinkle`, `shimmer`, `fire`, `spiral`, `butterfly`, `plasma`, `snow`, `strobe`, and the original `pulse`, `ripple`, `hold`. `meteors` exists but reads as scattered dots on a thin outline.
- **Whole-choir looks** on the `Outlines` group, one picture across all six trees: `choir_rainbow`, `choir_butterfly`, `choir_curtain`, `choir_galaxy`, `choir_spiral`, `choir_fire`, `choir_meteors`, `choir_snow`, `choir_shockwave` (too thin to see at choir scale so far).
- **Palettes**: `rainbow` (turns one step per tree, so hues run across the choir), `xmas`, `candy`, `ice`, `white`, or a list of colours.
- **Accents** on the layer above, on the beat: `flash`, `colour_hit`, `sparkle_hit`; `accent_every` thins them.
- **Eyes** on `StairTreeN/Eyes`: `blink` (default, Faces does it), `follow` (trees that aren't singing look at the ones that are), `roll`, `rainbow` (spinning), `sparkle`. The Faces effect's eyes are switched off wherever an eye move runs.

What goes where, and why, was settled by experiment (tools/fx.py docstring): never put effects on `Choir` (the whole trees), because the Faces effect's black is see-through and the colour opens the mouths. The `Outlines` group (the six Outline sub-models) was added to the layout on 23 Oct 2026 for that reason; existing sequences need it listed: `python -m tools.xsq "<sequence>"` with the sequence closed (Rockin' and Dominick done).

Settings keys come from `data/xlights-effects.json`, built from the xLights 2026.18 source by `python -m tools.xl_keys <source checkout>`; `tools/fx.py` refuses unknown keys, out-of-range values and unknown choices before anything reaches xLights. Decimal settings go in the text-box key (`E_TEXTCTRL_…`).

**See it without xLights**: `python -m tools.preview_render data/songs/<song>.json --start 30 --end 45` writes an animated GIF of the six trees to `previews/` (not committed); `--sheet 0:120:10` writes a contact sheet.
