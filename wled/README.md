# Setting up a tree controller by hand (M0, done 21 Oct 2026)

Tested on Rob's spare ESP32-WROOM-32 "mini" board with WLED 16.0.1 (plain ESP32 build) and xLights 2026.18 on the PC.

## Flash and configure WLED

1. USB data cable to the PC. Open https://install.wled.me in Chrome or Edge, pick the latest stable plain ESP32 build (not Audioreactive, not S3/C3), Install, pick the COM port. No COM port means a missing USB driver (CH9102/CH340: WCH; CP210x: Silicon Labs). Stuck on "Connecting…": hold BOOT.
2. Join Wi-Fi from the installer, then open the device's IP.
3. Config → LED Preferences: length 92, data GPIO 16, WS281x, colour order GRB (TBC at first light), brightness limiter left on. GPIO16 rather than the default GPIO2, which is a boot strapping pin and drives the onboard LED.
4. Config → Sync Interfaces: Receive UDP realtime ticked (DDP arrives through it).
5. Reserve the IP in the router.

What the working prototype reports (`/json/cfg`): `hw.led.ins[0]` = `{"start":0,"len":92,"pin":[16],"order":0,"type":22}` (order 0 = GRB, type 22 = WS281x); `if.live.en` = true. These are the values tools/gen_site_config.py should write.

## xLights → WLED over DDP

1. Controllers tab → Add Ethernet: name StairTree*N*, the tree's IP, protocol DDP, channels 276, Keep channel numbers off. Save.
2. Add controllers in slot order (StairTree1 first) so each one's global channel range lines up with the model start channels (1, 277, 553, …). Nothing changes on the Layout tab.
3. WLED web page → Peek (eye button) shows the frames with no pixels connected. Info shows realtime mode, DDP, and the sender's IP.
4. xLights Tools → Test, tick the controller, run a chase.

Confirmed working 21 Oct 2026: WLED reported `live: true, lm: "DDP", lip: 192.168.0.84` (the PC).
